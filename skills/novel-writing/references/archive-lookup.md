# 按需查阅故事档案

适用于续写或局部核对，不妨碍作者明确要求的全档审读。完整 `story-bible.md` 仍是唯一档案；查找工具直接读取其中的标准 Markdown 表，不写文件、不生成第二份索引，也不读章节正文。

1. 需要核对小说、分支或已有范围时，用 `overview` 快览，不读整张指纹表；概况不是对每条事实的保证。先从接续段和写作要求列出本场景必须延续的物件、约定、人物关系或未解线索。作者明确指定的限制照常读取。
2. 已知编号直接 `read --event`。不知道编号，先以一两个具体物件或动作 `find`，从短预览选少量条目。默认查 `event`；查物件规则用 `rule`，查待确认用 `pending`，查约定和揭晓用 `thread`，查别名用 `person`。查人物在接续时的状态，先从人物索引和档案确认准确的名字、状态项，再用 `state --before`，不用关键词的前几条推定当时状态。优先检查场景里的异常是否对应旧约定；预览只作定位。
3. 用 `read --event` 取选中的完整事件。非事件行用 `--line` 取刚看到的 `L` 后面数字；档案编辑后先重新定位。按完整记录上的章号和出处选 `--source`，只取当前采用稿相关的路径和指纹；不凭事件编号猜章号，不因为某条列了多个关联事件就全取。再做[版本核对](continuity-watcher.md#文件版本核对)。若待复核、改动或矛盾只影响一处，读取对应原文段落，不把核对扩大成全章。

在小说项目根目录执行；`<查询脚本>` 是 [query_story_archive.py](../scripts/query_story_archive.py) 的实际路径。选项可重复；例子里的档案是默认路径 `story-bible.md`，自定义路径用 `--archive` 放在子命令前。

```text
python <查询脚本> overview
python <查询脚本> find --term 铜匣 --term 绑带
python <查询脚本> find --term 布角 --kind pending
python <查询脚本> read --event E-042 --line 170 --source chapters/12.md
python <查询脚本> state --person 蒋禾 --item 与秦乌的关系 --before 300.2
python <查询脚本> impact --event E-042
```

`state` 按标准人物状态表匹配人物名和状态项，查找**严格早于**给定位置的最新一条：`300` 是第 300 章开头，`300.2` 是第 300 章第二场开头。`300.1` 会早于 `300.2`；只有章号而没有场次的第 300 章记录不能推定为第二场前。同一生效点重叠或旧格式无法定序时，命令提示回查，不挑一条猜。输出是档案记录，不代表来源已核对。倒叙、同场插写及需要以故事时间为准的情况仍定点回查。

`impact` 只列档案中引用该事件编号的直接依赖，按章和已知的场次排列；同章无场次的只作定位。不需要事件仍存在，适合回查删改前的编号。默认最多 8 条；按输出的 `--offset` 说明分批取。结果是待核对位置，不证明有冲突；没有记录也不证明安全。不读取或修改正文。

`find` 默认每个搜索词最多返回两个预览；只有确实需要区分多个候选时才提高它的 `--limit`。没有 Python、档案特殊格式无法识别、确切事件找不到时，退回按具体词或编号搜索档案，再只读命中的几行；先找变体或待确认表，仍无证据且会影响情节才定点回查旧稿或请作者确认。档案没有记录，不代表原稿没有埋伏笔。
