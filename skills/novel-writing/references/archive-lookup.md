# 按需查阅故事档案

适用于续写或局部核对，不妨碍作者明确要求的全档审读。完整 `story-bible.md` 仍是唯一档案；查找工具直接读取其中的标准 Markdown 表，不写文件、不生成第二份索引，也不读章节正文。

1. 需要核对小说、分支或已有范围时，用 `overview` 快览，不读整张指纹表；概况不是对每条事实的保证。先从接续段和写作要求列出本场景必须延续的物件、约定、人物关系或未解线索。作者明确指定的限制照常读取。
2. 已知编号直接 `read --event`。不知道编号，先以一两个具体物件、动作或状态项 `find`，从短预览里选少量条目。常见名字只用于区分同名条目，不单独搜索贯穿全书的主角名。默认查 `event`；查物件怎么用或有哪些限制，查 `rule`；查一时找不到出处的线索，试 `pending` 或具体同义词；查约定和揭晓用 `thread`，查生效状态或别名用 `state` 或 `person`。优先检查场景里的异常是否对应旧约定；不要因为第一个候选匹配就忽略指定目标。预览只是定位用，不当事实依据。
3. 用 `read --event` 取选中的完整事件。非事件行用 `--line` 取刚看到的 `L` 后面数字；档案编辑后先重新定位。按完整记录上的章号和出处选 `--source`，只取当前采用稿相关的路径和指纹；不凭事件编号猜章号，不因为某条列了多个关联事件就全取。再做[版本核对](continuity-watcher.md#文件版本核对)。若待复核、改动或矛盾只影响一处，读取对应原文段落，不把核对扩大成全章。

在小说项目根目录执行；`<查询脚本>` 是 [query_story_archive.py](../scripts/query_story_archive.py) 的实际路径。选项可重复；例子里的档案是默认路径 `story-bible.md`，自定义路径用 `--archive` 放在子命令前。

```text
python <查询脚本> overview
python <查询脚本> find --term 铜匣 --term 绑带
python <查询脚本> find --term 布角 --kind pending
python <查询脚本> read --event E-042 --line 170 --source chapters/12.md
```

默认每个搜索词最多返回两个预览；只有确实需要区分多个候选时才提高 `--limit`。没有 Python、档案特殊格式无法识别、确切事件找不到时，退回按具体词或编号搜索档案，再只读命中的几行；先找变体或待确认表，仍无证据且会影响情节才定点回查旧稿或请作者确认。档案没有记录，不代表原稿没有埋伏笔。
