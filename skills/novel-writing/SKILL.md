# 小说创作

按用户要求交付当前阶段的内容。默认沿用用户的语言；续写或改稿时，以现有稿件的语体为基准。不要把自己的建议当成作者已确认的设定。

## 先选工作模式

| 请求 | 交付重点 |
| --- | --- |
| 构思、人物、世界观、大纲 | 把概念变成推动剧情的选择、代价与后果；用户在选方向时，再给少量真正不同的方案。 |
| 设计、试写、续写、改写或审读开篇／首个剧情闭环 | 用[开篇与首个剧情闭环](references/opening-arc.md)检查追读、选择与兑现。涉及正文时，通用正文流程照走，再做开篇专项检查；纯大纲不必写样稿。 |
| 规划或审读中后段剧情、收卷与换卷 | 用[分卷推进与兑现](references/serial-arcs.md)定位读者正在等什么、本卷兑现了什么、下一卷如何承接。单章续写仅在影响当前剧情阶段或碰到卷界时加载。 |
| 写正文、续写 | 直接给可读正文。续写先确认采用稿与接续点，再按[续写取样](references/story-craft.md#续写取样)延续原稿声音，不复述整章。 |
| 润色、重写 | 先判断改动范围。润色不改事件、线索或结局；结构重写在授权范围内调整，并标出会影响后文的变化。 |
| 审读、找矛盾 | 按影响排序，给出文本位置、判断依据与最小修复建议。明确区分确定矛盾、文本留白和个人偏好；「只审不改」不写正文或档案，即使已开启持续维护。 |
| 启用监视者、归档章节、使用已维护的故事档案续写 | 按[连续性监视者](references/continuity-watcher.md)行事。先用档案定位，只读必要原文；有写入授权时增量归档，不把试稿视为定稿。 |

构思、大纲需要更细的方法时，读 [叙事与改稿](references/story-craft.md)。续写、跨章节改动或连续性审读时，读 [长篇连续性](references/continuity.md)。

写、续写、改写或审读含有实质交手的场景（如比武、斗法、争夺或边打边撤）时，另读 [打斗场面](references/combat-scenes.md)，检查决定输赢或脱身的关键动作。非打斗场景不用加载。

## 创作边界

- 从用户给出的材料和指定章节开始。缺少非关键细节时可采用可逆的创作假设；只有关乎整体方向、接续点或设定冲突且无法从材料判断时，才提一个聚焦的问题。
- 优先尊重作者明确确认的事实和当前明确授权的变更。原稿、旧大纲、角色猜测和读者已知信息互不等同；不要凭推断弥合实质冲突。
- 用人物当下想要什么、害怕失去什么来驱动行动。让场景在信息、关系、处境或决定上产生变化；伏笔与转折应有正文可追溯的依据。
- 写、续写、改写或审读正文时，不论题材或篇幅，包括开篇及首个剧情闭环，先读[人物、场景与氛围](references/story-craft.md#人物场景与氛围)和[神情、语气与情绪节奏](references/story-craft.md#神情语气与情绪节奏)。按[正文自校](references/story-craft.md#让场景读起来连贯)模拟首读：既查读者怎么理解、人物怎么回应、事情因此怎么变，也查人物与现场有没有具体可感的依据。在用户授权内修订，再把改处放回前后文连读。小段只查交付片段及可用的接续；只审不改时，指出问题，不动原稿。
- 用户说“只要正文”时，不附工作计划、修改说明或连续性报告。用户给出字数或章节界限时，在范围内收束一个完整段落或场景；别用概述冒充正文。
- 默认在对话交付。用户要求保存或修改文件时，只处理明确相关的路径；不把未确认提案写成既定事实，不自行发布稿件。需要建立长篇档案且用户要求落盘时，可采用 [故事档案模板](assets/story-bible-template.md)，只保留有用栏目。
